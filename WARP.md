# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Repository Overview

This is an academic portfolio website built with Quarto and hosted on GitHub Pages. It contains research publications, teaching materials, blog posts, and personal information for Jacob Downs, an assistant professor at the University of Montana.

## Architecture

### Site Structure
- **Root level**: Main pages (index, research, teaching, about) as `.qmd` files
- **posts/**: Blog posts and writing, with each post as a dated `.qmd` file
  - `_metadata.yml`: Default formatting configuration for all posts
  - `index.qmd`: Auto-generates listing page from post contents
- **_site/**: Generated static site output (gitignored, do not edit directly)
- **images/**: Static image assets referenced in content
- **_quarto.yml**: Global site configuration (navigation, theme, bibliography)
- **references.bib**: BibTeX bibliography for academic citations
- **styles.css**: Custom CSS overrides

### Quarto Configuration
The site uses Quarto's website project type with:
- **Theme**: Cosmo (Bootstrap-based)
- **Citations**: IEEE style via CSL, referencing `references.bib`
- **Navigation**: Top navbar with Home, Research, Teaching, Writing, About
- **Output**: HTML with right-side TOC and smooth scrolling

### Deployment
Automated via GitHub Actions (`.github/workflows/publish.yml`):
1. Triggers on push to `main` branch
2. Sets up Quarto environment
3. Runs `quarto render` to build `_site/`
4. Deploys to GitHub Pages

## Development Commands

### Build and Preview
```bash
# Render the entire site (generates _site/)
quarto render

# Preview site with live reload (opens browser at http://localhost:4200)
quarto preview

# Render a single file
quarto render path/to/file.qmd
```

### Content Creation

#### Adding a New Blog Post
1. Create a new `.qmd` file in `posts/` with naming: `YYYY-MM-DD-title.qmd`
2. Include frontmatter with at minimum:
   ```yaml
   ---
   title: "Post Title"
   date: YYYY-MM-DD
   categories: [category1, category2]
   ---
   ```
3. The post automatically appears in `posts/index.qmd` listing

#### Adding Citations
1. Add BibTeX entry to `references.bib`
2. Reference in `.qmd` files using `[@citation_key]`
3. For nocite (show in bibliography without inline citation), use frontmatter:
   ```yaml
   nocite: |
     @citation_key1
     @citation_key2
   ```

### Project Structure Commands
```bash
# Check Quarto version
quarto --version

# Validate project configuration
quarto check

# Clean build artifacts
rm -rf _site/ .quarto/
```

## File Conventions

### Content Files
- All content pages use `.qmd` (Quarto Markdown) format
- Frontmatter is YAML between `---` delimiters
- Posts must include `title`, `date`, and `categories` in frontmatter

### Citations
- Academic references stored in `references.bib` (BibTeX format)
- Citation keys follow format: `authorlastname_titleword_year`
- Use IEEE citation style (configured globally in `_quarto.yml`)

### Images
- Store in `images/` directory
- Reference using relative paths: `images/filename.ext`
- Use Quarto image syntax for captions: `![caption](path){options}`

## Important Notes

- **Do not manually edit `_site/`**: This directory is auto-generated by `quarto render`
- **GitHub Actions handles deployment**: No manual deployment steps needed after pushing to `main`
- **Quarto must be installed locally** to build/preview the site (not present in current environment)
- **Bibliography changes**: After editing `references.bib`, re-render affected pages to update citations
- **Post listing is automatic**: The `posts/index.qmd` uses Quarto's listing feature to auto-populate from post files
